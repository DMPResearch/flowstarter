## What is holding the number down

Of the 16 journeys that are not ready:

- 7 are short on unit coverage of their API handlers.
- 9 have no Playwright spec that walks them, or have one that failed.
- 14 are never checked against the deployed site.

The production check is the binding constraint. `e2e/prod-synthetic.spec.ts` reads three pages, one health endpoint, one webhook and one static bundle; every other journey is unproved in production by definition.

## The journeys

### A visitor talks to the intake agent and gets a brief

`intake-conversation`, tier 1, not ready. Spec: `e2e/contract.spec.ts`.

The contract spec posts a minimal valid payload, a payload that fails the schema, and a cross-origin payload the CSRF check refuses. It proves the endpoint's contract, not that a whole conversation reaches a usable brief.

### The info agent asks the follow-up questions the brief is missing

`info-agent-followup`, tier 1, not ready. Spec: none.

No E2E spec walks the graph. The sufficiency rules and the graph transitions are unit-tested in src/lib/flowstarter/intake-graph and src/lib/flowstarter/sufficiency.ts; nothing checks them through HTTP.

### The pipeline generates a preview site from the brief

`preview-generation`, tier 2, not ready. Spec: none.

Generation calls a model through OpenRouter and takes minutes, so it cannot run in a per-pull-request lane. It belongs in the staging full-journey tier, which has no spec yet.

### The visitor gets two free edits on the preview

`two-free-edits`, tier 2, not ready. Spec: none.

The two-edit allowance is a rule in deterministic code, not a prompt. Unit-tested; no E2E spec spends the allowance and checks the third edit is refused.

### The visitor pays the deposit and Stripe confirms it

`deposit-checkout`, tier 3, money path, not ready. Spec: `e2e/contract.spec.ts`.

The contract spec proves the Stripe webhook refuses an unsigned POST and never 500s, and the production synthetic repeats that against flowstarter.net. Nothing drives a real test-mode checkout end to end.

### The payer gets an account against the email they paid with

`account-by-email`, tier 2, money path, not ready. Spec: none.

Guest provisioning happens inside the Stripe webhook handler (src/lib/flowstarter/guest-credentials.ts) and forces a password change on first sign-in. Unit-tested; no E2E spec signs in as a freshly provisioned client.

### The client claims the workspace their preview became

`workspace-claim`, tier 2, not ready. Spec: none.

src/lib/flowstarter/claim.ts is the widest-tested module in the journey set. The gap is HTTP: no spec claims a workspace, and none proves a second claim on the same workspace is refused.

### The operator watches the build on the board and leaves a note for the agent

`build-board-team-note`, tier 2, not ready. Spec: `e2e/dashboards.spec.ts`.

dashboards.spec.ts opens the board unauthenticated and proves it does not crash. The authenticated half -- a note reaching the agent and coming back in the job log -- has no spec.

### The full site is built and published on a real host

`site-published`, tier 4, not ready. Spec: `e2e/prod-synthetic.spec.ts`.

The production synthetic checks a generated static bundle is reachable on flowstarter.net. A real deploy needs an allocated Hetzner host and the per-host deploy agent, so the full path cannot run in CI today.

### The client pays the balance on the final invoice

`balance-payment`, tier 3, money path, not ready. Spec: none.

Invoice creation and the portal link are unit-tested against a mocked Stripe. No spec sends an invoice and sees it paid.

### The client signs in and finds their project

`client-dashboard`, tier 2, not ready. Spec: `e2e/dashboards.spec.ts`.

Covered unauthenticated: the client surfaces render and the guard sends a signed-out visitor to login (concierge-flow.spec.ts and contract.spec.ts both check the redirect). Signed in, nothing is checked.

### The client makes a small change in the editor and the site rebuilds

`editor-small-change-rebuild`, tier 2, not ready. Spec: none.

The size rule that decides rebuild-now versus quote-it lives in src/lib/flowstarter/site-editor.ts and is unit-tested. No spec edits, applies and publishes.

### A bigger change is quoted and the client pays for it

`change-request-quoted-paid`, tier 3, money path, not ready. Spec: none.

Quoting and the checkout for a quoted change (src/lib/flowstarter/change-request-checkout.ts) are the newest money path and the least covered. No E2E spec.

### The client's own domain serves the site

`custom-domain`, tier 4, not ready. Spec: `e2e/dashboards.spec.ts`.

The domains page is checked for not crashing. Verification writes real Cloudflare DNS, so the journey cannot complete in CI; src/lib/hosting/cloudflare.ts carries the unit tests instead.

### An operator is invited and lands in the right role

`operator-invite-roles`, tier 2, not ready. Spec: `e2e/dashboards.spec.ts`.

The invite page is checked for not crashing. Roles are resolved by resolveUserRole in src/lib/api-auth.ts and proved in unit tests; no spec accepts an invitation.

### A client cancels, and money already taken comes back

`cancellation-and-refunds`, tier 3, money path, not ready. Spec: none.

Half built. Cancelling a subscription is a real endpoint. Refunds are NOT built: src/lib/billing/stripe.ts says refunds are handled separately, and src/lib/flowstarter/guest-deposit.ts leaves a failed provisioning loud enough to be refunded by hand. There is no refund endpoint and no refund path in the product.
